## Introduction

The **values_50_75_25** subapplication provides three constant REAL values (50.0, 75.0, and 25.0) as outputs via unidirectional AR adapters. It is designed to supply fixed setpoints to a downstream selection logic, such as an `AR_AUI_MUX_3` block, where the selection index `K` maps to one of the three constant values. The subapplication encapsulates three independent constant sources, each implemented using an internal `initval_AR` function block.

## Interface Structure

The subapplication exposes only adapter outputs; it has no event inputs, event outputs, data inputs, or data outputs.

### **Event Inputs**

None.

### **Event Outputs**

None.

### **Data Inputs**

None.

### **Data Outputs**

None.

### **Adapters**

| Adapter Name | Type                      | Description           |
|--------------|---------------------------|-----------------------|
| OUT_50       | unidirectional::AR         | Fixed value 50.0      |
| OUT_75       | unidirectional::AR         | Fixed value 75.0      |
| OUT_25       | unidirectional::AR         | Fixed value 25.0      |

All adapters are of type `adapter::types::unidirectional::AR`, representing a unidirectional connection that carries a REAL value.

## Functionality

The subapplication internally instantiates three `initval_AR` function blocks, each parameterized with a specific initial value:

- `initval_AR_50` with `INIT_VAL = 50.0`
- `initval_AR_75` with `INIT_VAL = 75.0`
- `initval_AR_25` with `INIT_VAL = 25.0`

Each block writes its constant to its `OUT` adapter, which is directly connected to the corresponding subapplication adapter output. Thus, the subapplication continually provides the three predefined constant values on its outputs.

## Technical Features

- **Pure constant output:** No dynamic calculation or external inputs are involved; the values are fixed at design time.
- **Unidirectional adapters:** The AR adapter type is specifically designed for continuous value transfer from producer to consumer without handshaking.
- **Parameterization:** The internal `initval_AR` blocks are simple and robust, ensuring immediate availability of the output values.
- **Separation of concerns:** The subapplication isolates constant generation, making the source of different setpoints explicit and exchangeable.

## State Overview

This subapplication is stateless. The internal function blocks are combinatorial in nature (or initial value based) and do not maintain any runtime state. Outputs are available as soon as the subapplication is activated.

## Application Scenarios

- **Setpoint selection for automation tasks:** Used in conjunction with a multiplexer (e.g., `AR_AUI_MUX_3`) where different constant outputs (50, 75, 25) are selected via an index.
- **Test and simulation environments:** Provide fixed reference values for validating control algorithms or monitoring logic.
- **Reusable constant library:** The subapplication can be instantiated multiple times in a project to supply identical constant values without duplicating individual function blocks.

## Comparison with Similar Blocks

- **vs. simple constant function block:** A single constant block provides only one value; this subapplication encapsulates three related constants with dedicated outputs, improving readability and maintainability.
- **vs. parameterized subapplication:** If the constants were dynamic, a subapplication would require data inputs. Here, because the values are fixed, the adapter-only interface is sufficient and simplifies external wiring.
- **vs. direct use of internal blocks:** By hiding the internal implementation, the subapplication offers a clean interface and makes the intended logic (three distinct setpoints) immediately obvious to other engineers.

## Conclusion

The `values_50_75_25` subapplication is a straightforward solution for providing three fixed REAL constants via unidirectional adapters. Its simplicity, clear naming, and encapsulation make it ideal for use in selector or multiplexer scenarios where predefined setpoints are required. With no dynamic parts, it is easy to integrate and guarantees consistent output values across the entire runtime.
